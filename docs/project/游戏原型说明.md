# 单人游戏原型

## 含弘门场景

当前 Phaser 原型从 [00 含弘门入口](../../picture/pixel_swu_ground_6zones_v1/maps/00_hanhong_gate.tmx) 出发，可经边界道路双向往返 01 校门外衔接区、02 东侧樟林、03 西侧樟林和 04 雕像花园。04 雕像花园北口与 05 行署路南口双向连通。

运行 `npm run dev`，打开终端显示的地址，可同时启动 Web 与 API，Vite 在开发模式下提供热更新。组合 WASD、方向键或页面方向按钮可八向移动，按住 Shift 疾跑；斜向步长按距离增加时长，遇障碍可沿可通行轴滑动。Canvas 尺寸默认选择“随父级（原画）”：实际画布像素宽高随父容器变化，按 1:1 像素比例和像素画采样渲染，不额外提高内部清晰度；也可切换 384×240、768×480、1152×720、1536×960、1920×1200、2560×1600 预设。镜头默认 ZOOM 为 1×，该倍率在屏幕上的角色大小相当于旧版 1.5×；可在数值输入框直接设置正数倍率，也可使用滚轮按比例缩放，不设固定倍率范围。切换画布尺寸不改变 ZOOM，摄像机内部倍率按画布实际显示宽度换算，保证同一 ZOOM 在各档尺寸下的屏幕大小一致。镜头可滚动边界按当前画布和倍率动态扩展，超出拼接地图范围的部分使用地图背景色填充；矩形包围范围内没有地图的空缺也不能行走。按住鼠标中键移动至少 4 个屏幕像素可脱离角色跟随并平移画面，单击中键或点击“复位视角”恢复跟随与 1× 倍率。画面外为浅色调试台，显示角色脚底与渲染坐标、画面中心世界坐标、朝向、速度、室外维度、当前地图分区、地图对象与碰撞数量、纹理资源数和 Phaser 实时帧率；数据按约 50 毫秒刷新。Tile 轮廓下拉栏可关闭、按类别显示或逐格显示：类别取每格最上层的非空 TMX 图层，相邻同类别格子之间不画线。两种轮廓均在屏幕像素层按固定 1 像素绘制，镜头缩放和平移时对齐屏幕像素。镜头与角色的渲染位置在每帧渲染前统一对齐到画布像素，避免非整数缩放时各贴图分别取整造成的移动抖动；移动目标与碰撞判定仍使用逻辑坐标。

调试栏的“碰撞框”可独立开关：红框显示 TMX 碰撞矩形，青框显示玩家贴图范围，黄十字显示实际用于移动判定的脚底点。当前六区 TMX 未配置碰撞矩形，因此红框可能为空；地图外边界仍由移动规则阻挡。

“对象调试框”可选择关闭、交互与传送、特殊实体或全部，独立于碰撞框和 Tile 轮廓。黄框显示 TMX `Interactions` 区域，蓝框显示 `Portals` 传送区，紫框显示其他对象层中的特殊实体与建筑占位，并在框内显示名称；地图信息同时列出各类数量。当前六区尚无 `Interactions` 对象，建筑占位只是规划区域，不会阻挡移动。这些 Portals 矩形只保留为接缝参考标记，不再触发传送；调试框本身不改变通行行为。

## 地图与坐标

每区大小为 100 × 74 格，每格 16 × 16 像素。角色首次从 00 的 `Spawn/player_start` 出生，目前为 `(800, 896)`，每次移动一格。东西出口的 y 范围为 496–720，南北出口的 x 范围为 688–928，含端点。六区一次绘制在同一个 Phaser 场景中，跨接缝沿原方向连续移动，不重置脚底坐标或镜头。页面显示当前区域和全局游戏像素坐标，地图尺寸及对象统计为六区整体。

在 Tiled 编辑并保存 TMX 即可更新地图。地形图集位于地图目录的同级 `assets`。解析在 `gateMap.ts`，移动判定在 `campus.ts`，渲染、小鸟动画与只读调试快照在 `CampusScene.ts`。资源数分别表示当前已加载纹理数及工程声明的图片路径数，不代表显存占用；速度显示当前移动指令对应的像素每秒，静止时为零。游戏网格坐标不等于真实校园地理坐标。

本场景用于本地单人预览。多人位置裁决及与真实校园地理坐标的映射属于后续工作。

### 六区拼接布局（2026-11-09）

本次范围为本地单人原型六区连续拼接；保留现有道路通道，不增加地图或服务端协议。以 00 左上角为 `(0, 0)`，X 向右、Y 向下，所有偏移单位为游戏像素：

| 地图 | 左上角偏移 |
|---|---|
| 00 含弘门 | `(0, 0)` |
| 01 校门外衔接区 | `(0, 1184)` |
| 02 东侧樟林 | `(1600, 0)` |
| 03 西侧樟林 | `(-1600, 0)` |
| 04 雕像花园 | `(0, -1184)` |
| 05 行署路 | `(0, -2368)` |

接缝分别为 00→02 的 X=1600、03→00 的 X=0（Y=496–720），04→00 的 Y=0、00→01 的 Y=1184、05→04 的 Y=-1184（X=688–928），均双向开放且包含通道端点；其他边缘和空缺禁止进入。斜向移动按轨迹与接缝的实际交点校验。

`campus.ts` 保存偏移、世界范围和通行规则；`gateMap.ts` 在读取后平移出生点、贴图、碰撞、交互及参考对象，TMX 源文件仍保持局部坐标。完整区域尺寸必须为 1600×1184、格子为 16，否则解析报错，避免编辑后静默错位。地面绘制深度低于负 Y 区域的角色和实体。包围范围为 X=[-1600,3200)、Y=[-2368,2368)，大小 4800×4736。

兼容影响：调试和状态栏的角色坐标改为全局游戏坐标；无数据库迁移、HTTP/Socket.IO 或插件契约变更。回退时恢复按区加载及局部坐标移动逻辑，TMX 无需迁移。真实校园坐标校准、多人服务端权威和最终视角仍未解决，本次未接入校园数据。

本次验证：`npm run typecheck`、`npm test`（5 项移动/接缝/碰撞测试）、Web 生产构建及 `git diff --check` 均通过。构建提示 Phaser 分包超过 500 kB；尚未完成浏览器画面与帧率实测，未统计覆盖率，不代表整体 MVP 质量门禁已达成。

### 右上角小地图（2026-11-09）

第一版提供六区全局总览：游戏画面右上角显示约 200px 的地图面板，窄屏（≤630px）缩为 140px。地形来自现有六张 TMX 的瓦片图层，等比例缩略并缓存为 600×592 的透明底图；无地图区域留空。标注六区名称，当前区域以黄色边框高亮，黄色圆点和箭头表示玩家及朝向，白框表示当前镜头可见范围。底图不包含独立建筑贴图和实体。

`CampusMinimap.vue` 负责 Canvas UI、折叠按钮、尺寸观察与绘制；`minimap.ts` 提供类型化只读快照及统一坐标投影。`CampusScene` 仅提供缓存底图与只读位置/镜头快照，`App.vue` 每 50ms 更新动态数据。玩家使用渲染位置保证跨区移动平滑，镜头使用真实中心和缩放后的世界范围。折叠时停止快照更新和绘制，展开后恢复，组件卸载时清理尺寸观察器。小地图范围内的鼠标、滚轮和键盘事件不传播到游戏输入，面板之外保持原有操作。

范围与兼容：仅本地单人预览 UI；沿用既有全局游戏坐标、地图授权及插件边界，无 API、Socket.IO、数据库或地理坐标契约变更。不提供点击传送、导航或拖拽。删除组件入口及小地图数据接口即可回退，TMX 无需迁移。

验证：全项目 `npm run typecheck`、`npm test`（6 项，新增负坐标、缩放比例、镜头矩形映射测试）、Web 生产构建通过。浏览器中确认 1440px 桌面和约 510px 窄屏布局、地形与标记显示、折叠/展开。现有 Phaser 大分包警告仍存在；浏览器检查时 API 未连接。尚未进行跨区行走全流程及性能压测，未统计覆盖率，不能据此认定整体 MVP 门禁通过。
