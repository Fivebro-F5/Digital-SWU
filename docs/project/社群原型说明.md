# 社群 UI 原型（校园像素风）

2026-11-17 用户要求：接入 Argon Social 的社交动态发帖与好友群组聊天功能，不实现完整业务，优先把 UI 与 UI 操作跑通，交付可交互的全流程原型；随后按“补齐 UI”要求扩展主页、设置与消息/通知等剩余界面。入口为游戏屏幕内右侧的“社群”按钮，并绑定快捷键 `P`。

最初的功能页面参考 [ArtMin96/argon-social](https://github.com/ArtMin96/argon-social) 的 Newsfeed、Messenger、Profile、Settings 页面分类，未引入其代码或依赖。2026-11-17 用户进一步要求统一改为像素风、像素字体与 SVG 符号，并避免页面元素互相遮挡；现有视觉已改用校园绿、暖纸色、方角边框和整格阴影。Sign In / Sign Up 页面留待身份会话一起实现（见待决策 D-09），当前以固定本地演示账号代替。

社群面板使用随包加载的 [Fusion Pixel Font](https://github.com/TakWolf/fusion-pixel-font) 12px 简体中文 WOFF2，字体按 [SIL OFL 1.1](../../apps/web/src/components/community/fonts/OFL.txt) 授权；图标由 `PixelIcon.vue` 提供同一 16×16 SVG 整数网格，不使用 emoji 图标。面板最宽 680px，窄屏占满游戏画面。通知展开后在页签上方占用独立空间；聊天宽屏双栏，窄屏在会话列表与聊天窗口间切换；好友请求的操作按钮单独成行。正文可换行，长昵称和预览文字截断，操作按钮与输入框在窄屏自动换行。关闭面板后焦点回到“社群”入口，`Esc` 在输入框内也可关闭。

字体来自官方 2026.11.10 发行包；`fonts/OFL.txt` 和 `fonts/LICENSES/` 保留发行包附带的授权文本。社群 UI 只改变前端显示与局部交互，不影响服务端权限或游戏坐标契约。

## 入口与操作

- 游戏屏幕右侧边缘有竖排“社群”按钮，点击或按 `P` 打开面板；再按 `P` 或 `Esc`、点右上角 × 关闭。
- 面板为游戏画面内的右侧抽屉（宽 ≤680px，窄屏占满），含“动态 / 消息 / 主页 / 设置”四个页签与通知符号。
- 面板打开期间角色移动与 E/空格交互暂停（复用对话的覆盖层暂停机制，见 `CampusScene` 的 `isOverlayOpen` 钩子）；在输入框内打字时不触发 `P` 快捷键，`Esc` 仍可关闭；对话打开时 `P` 不生效。
- 输入提示卡已更新为“WASD / 方向键八向移动 · Shift 疾跑 · E / 空格交互 · P 社群”。

## 已跑通的 UI 流程

动态（Newsfeed）：
- 浏览演示动态流（作者、角色、时间、正文），支持按作者或内容搜索；
- “含弘门往北的六区接缝……”演示动态附有一张随 Web 构建打包的本地截图，帖子图片使用可选字段与替代文本，按原比例显示；这不表示图片上传已开放；
- 发布新动态（文本 ≤500 字，发布后置顶显示“刚刚”，并有成功提示）；
- 点赞/取消点赞（数量实时变化）；
- 展开评论并添加评论（本地即时回显）；
- 删除自己发布的动态（带确认）；
- “上传暂不可用”按钮按设计保留但禁用，提示图片上传依赖 MinIO（见待决策 D-11）。

消息（Messenger）：
- 好友、群组与临时对话分组的会话列表（头像、最后一条消息、时间、未读角标）；
- 好友请求区：接受（加入好友列表）或拒绝；
- “＋ 添加”按昵称添加好友（演示）、“＋ 新建群聊”创建空群组并自动选中；
- 点击会话打开聊天窗口并清零未读，气泡式消息流（自己的消息右侧渐变气泡）；
- 输入文字按回车或点“发送”即时出现在会话中（本地回显，不产生网络请求）。
- 点击地图上的路人 NPC，或靠近路人按 E / 空格或点击画面内交互提示，直接打开该 NPC 的会话；未加好友时归入“临时对话”。在临时对话中点“添加好友”后，会话转入好友列表，原有消息保留；再次交互会复用同一会话。

主页（Profile）：
- 封面、头像、姓名与角色、简介、所在地与加入时间；
- 动态数、好友数、获赞数统计（由本地状态实时计算）；
- “我的动态”列表（可删除）；“编辑资料”跳转到设置页。

设置（Settings）：
- 基本资料（姓名、邮箱、电话、简介）、位置（含“主页公开位置”演示开关）、修改密码三组表单；
- 保存仅更新本地演示状态并提示“已保存（本地演示）”；密码表单明确标注不校验、不存储、不发送（D-09）。

通知：
- 面板头部的铃铛显示未读数量，下拉列出演示通知，可“全部已读”。

## 数据与状态

- 演示数据（用户、动态、会话、好友请求、通知）定义于 `demoData.ts`；所有页面共享的响应式内存状态与操作集中在 `store.ts`（发帖、点赞、评论、删帖、发消息、建群、加好友、接受/拒绝请求、通知已读、资料更新），刷新页面即全部还原。
- 路人身份由场景生成的 `npc-01` 至 `npc-50` 本地编号表示；临时会话和好友状态也只保存在当前页面内存中，刷新后重置。路人没有真实账号或聊天回复。
- 后续接入服务端时，把 `store.ts` 中的动作替换为经过身份校验的 HTTP / Socket.IO 调用即可，组件交互结构无需重写。
- 不发起任何 API / Socket.IO 请求，不代表已接入服务端、认证、审核或上传能力。

| `apps/web/src/components/community/ChatTab.vue` | 消息：会话列表、好友请求、聊天窗口、发送、加好友、建群 |

| `apps/web/src/components/community/store.ts` | 共享内存状态与操作层 |
| `apps/web/src/components/community/demoData.ts` | 类型与演示数据 |
| `apps/web/src/App.vue` | 社群按钮、`P`/`Esc` 快捷键、覆盖层暂停接线 |

契约影响：无 API、Socket.IO、数据库或插件契约变更。`GameHooks.isDialogOpen` 重命名为 `isOverlayOpen`，仅影响前端内部两个调用点。

2026-11-18 新增前端内部 `GameHooks.onNpcChat(id, name)`，用于场景向社群面板请求打开指定路人的会话；该编号不是服务端用户 ID，不构成正式好友关系。NPC 与聊天仍属于本地原型。

## 边界与未解决问题

- 本原型只是前端 UI，不承担权限判定。接入服务端时，发帖、评论、聊天、建群、好友请求与资料修改都必须经过服务端身份校验与 RBAC（与[架构与接口约定](../architecture/架构与接口约定.md)一致），并复用 Socket.IO 的事件级校验。
- 社区审核（D-05）与隐私规则（D-06）仍是待决策事项，社区功能正式上线前必须核定；当前演示数据不涉及真实个人信息。
- 登录/注册页未做：等注册登录与 Session（D-09）实现时一并接入。
- 未实现：真实好友关系、群组管理、消息历史、图片上传、@提及、站内信等；均为后续迭代范围。
