## 维护规则

项目概述记录需求来源。项目约束将已确定要求转为实施规则；架构与接口约定记录设计边界；待决策事项只记录尚未定案的问题。用户明确改变需求时，先更新概述或记录新需求来源，再同步修改受影响的文档，避免相互矛盾。

所有文件使用 UTF-8、Markdown 和相对链接。实际启动和检查命令见工程初始化说明；新增脚本时同步更新该说明。
