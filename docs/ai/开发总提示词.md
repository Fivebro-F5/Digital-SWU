你正在开发“数字西大”：基于 Web 的西南大学数字校园游戏化平台。先阅读仓库中的 docs/project/数字西大-项目概述.md、docs/project/项目约束.md、docs/architecture/架构与接口约定.md、docs/project/待决策事项.md。将概述视为需求来源，将约束和架构文档视为当前实施基线；遇到冲突时指出冲突，遵从用户最新明确要求并同步更新文档。不要把待决策事项当作已批准方案。

当前阶段是 MVP：打通微内核与插件、一个局部等距 2.5D 校园场景、玩家移动与地点交互、游客和注册登录、Socket.IO 多人同屏、PostGIS 地点与场景坐标映射。其他校园导览、社交和校园服务功能在后续迭代实现，不要擅自扩大本次任务。

遵循已选技术：Vue 3 + TypeScript + Vite、Phaser、NestJS + Node.js + TypeScript、PostgreSQL + PostGIS、Drizzle ORM + SQL、Socket.IO、内存缓存并预留 Redis、MinIO、Tiled + Phaser Editor。核心只管理插件注册、生命周期、服务发现、权限接口和异常；业务能力通过独立插件扩展。服务端维护多人游戏权威状态，地理坐标与游戏坐标分离。

所有权限都在服务端校验。使用 Session + Cookie + RBAC；Socket.IO 连接和事件同样验证身份与权限。不得收集或代存学校统一认证密码，不得绕过授权获取教务或校园数据。没有可靠数据的功能明确显示暂不可用，不编造数据或接入结果。

完成时列出实际改动、设计选择、已执行的命令及结果、未执行验证的原因、仍需决策的事项。不得声称未执行的测试或覆盖率已通过。项目目标门禁为核心模块行覆盖率 ≥80%、整体行覆盖率 ≥70%，关键流程有端到端测试；类型检查、静态检查和必需测试通过才能合入受保护分支。
