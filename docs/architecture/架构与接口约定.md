# 架构与接口约定

依据：[项目概述](../project/数字西大-项目概述.md)与[项目约束](../project/项目约束.md)。这是实现前的设计边界，不预设代码目录、具体字段、事件名或 API 路径；这些细节在对应任务中定义并记录。

## 1. 模块边界

| 模块 | 主要责任 | 不应承担 |
|---|---|---|
| 微内核 | 插件注册、生命周期、服务发现、权限接口、异常隔离 | 校园地图、社交或教务业务规则 |
| 地图插件 | 场景元数据、地点交互、坐标映射与空间查询 | 用户认证和全局会话管理 |
| 身份模块 | 游客、注册用户、Session、RBAC、统一认证适配接口 | 游戏移动裁决 |
| 实时模块 | Socket.IO 连接、场景房间、状态同步和重连 | 持久化业务数据的唯一来源 |
| 前端 UI | 页面、表单、状态展示与无障碍交互 | 服务端权限最终判定 |
| Phaser 场景 | 渲染、输入、插值、场景切换 | 玩家状态最终裁决 |

后续社交、通知与教务能力按独立插件/模块加入。首次实现时优先建立可扩展边界，避免为未开发模块制造空壳实现。

## 2. 插件契约

- 每个插件声明稳定标识、契约版本、依赖、提供的服务、权限需求及生命周期入口。
- 注册时校验依赖与版本；启动失败应可定位且不得让核心进入不可解释的半初始化状态。
- 同步调用使用类型化服务接口；异步通知使用事件总线。事件需定义名称、载荷、发布者、订阅者与兼容策略。
- 核心负责受控加载和卸载边界。动态插件加载仅保留能力，不在 MVP 中开放不受信任代码执行。
- 插件单元与契约测试覆盖正常、失败、缺依赖和版本不兼容路径。

## 3. 地图和坐标契约

- 地理坐标、游戏世界坐标、屏幕坐标分别建模，不混用单位。
- 每个场景记录其地理控制点、坐标参考、转换参数和版本；映射应可重复验证。
- PostGIS 存地点坐标、建筑范围和空间关系。客户端只接收任务所需的地点和几何信息。
- Tiled 的图层、碰撞和对象标识与 Phaser 场景交互逻辑建立明确映射。地点交互由服务端校验位置和权限。
- 室内、室外和鸟瞰是独立场景类型；MVP 只需交付一个局部等距场景。

## 4. HTTP 与实时通信契约

- HTTP 接口负责认证、静态/低频业务查询及持久化操作；Socket.IO 负责玩家在线状态和需要实时推送的事件。具体接口和事件在实现时记录请求、响应、错误码、权限及版本。
- Socket.IO 连接必须绑定服务端认可的身份与会话；事件级别继续校验权限、输入结构、频率和所属场景。
- 客户端发送意图或输入，服务端验证并更新权威状态；同步消息包含足够的实体标识、场景标识及顺序/时间信息，以处理乱序、重连和插值。
- 按场景分区推送，避免向无关玩家广播完整状态。断线重连后以服务端状态恢复，不信任客户端自报位置。

## 5. 数据及演进

- 数据模型及空间索引通过迁移维护。Drizzle 用于类型化常规访问，空间操作可使用经过参数化处理的 SQL。
- Session 与业务数据持久化，内存缓存只持有临时可重建状态。Redis 适配接口可预留，但不要求 MVP 部署 Redis。
- MinIO 保存上传文件；文件元数据、所属用户和访问权限在业务数据中管理。
- 改动插件契约、地图格式、数据库结构或实时事件时，说明兼容性、迁移及回滚路径，并补对应测试。
